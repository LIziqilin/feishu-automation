# 计划任务 -1073741510 假故障排查（自伤型误报）

**日期**：2026-09-16 14:30–15:03
**结论**：**非系统缺陷**——系诊断操作自伤，属观测者效应（Observer Effect）

---

## 一、现象

`V16_ServiceWatchdog` 连续两次调度报 `上次结果 = -1073741510`（0xC000013A = STATUS_CONTROL_C_EXIT），
且**无证据文件产出**：

| 运行时间 | rc | 证据 |
|---|---|---|
| 14:15:00 | 0 | watchdog_20260916-141505 ✅ |
| 14:30:00 | -1073741510 | **无** ❌ |
| 14:45:00 | -1073741510 | **无** ❌ |
| 14:47:49（手动触发） | 0 | watchdog_20260916-144754 ✅ |
| **15:00:00（静默）** | **0** | **watchdog_20260916-150005** ✅ |

对照实验呈现明显规律：**凡我手动/诊断触发的都成功，凡调度触发期间我在跑诊断命令的都失败**。

---

## 二、根因

`-1073741510` = `STATUS_CONTROL_C_EXIT`（进程收到 Ctrl+C / 控制台中断信号被终止），
**不是崩溃、不是脚本报错、不是权限问题**。

根因链：
1. 诊断期间，我在同一控制台会话内运行了 `taskkill /F /IM Obsidian.exe /T`、
   `taskkill /F /IM AnythingLLM.exe` 等命令；
2. Windows 计划任务以 `InteractiveToken`（交互式会话）运行 python.exe，与我的 exec 会话**共享控制台组**；
3. `taskkill /T` 杀进程树 / 控制台中断信号**波及同组的调度 python**，使其收到 CTRL_C 而退出；
4. 脚本尚未走到写证据那一步就被杀 → **无证据文件**（这正是"无输出"的真实原因）。

**决定性验证**：14:48–15:03 我**停止一切 exec 操作、静默等待**，15:00 调度**自然成功 rc=0**
并产出 `watchdog_20260916-150005.json`（3/3）。→ 排除系统缺陷。

---

## 三、为何不是系统缺陷

| 假设 | 证据 | 判定 |
|---|---|---|
| 任务注册又损坏（R-17 复发） | 手动触发 rc=0；静默调度 rc=0 | ❌ 排除 |
| 脚本崩溃 | 同脚本手动跑 rc=0、产出证据 | ❌ 排除 |
| 权限/RunLevel 问题 | V16_HourlyBackup（无 RunLevel）与 Watchdog（HighestAvailable）行为一致 | ❌ 排除 |
| 编码问题 | 已修 PYTHONUTF8=1，且手动跑正常 | ❌ 排除 |
| **诊断自伤（控制台组中断）** | **静默后立即恢复** | ✅ **成立** |

## 四、经验教训（写入施工纪律）

1. **验收期间禁止并发破坏性操作**：跑调度任务观察时，不得同会话执行 `taskkill /T`、
   服务重启、端口清障等操作——会污染观测结果，制造**假故障**。
2. **区分错误码语义**：
   - `0xC000013A`（-1073741510）= 外部中断，**不是**脚本失败
   - `0xC000013E`/其他 = 需进一步排查
   - `267009` = 任务运行中（正常）；`267011` = 从未运行（正常，如登录触发任务）
3. **无证据 ≠ 失败**：脚本在被中断时来不及写证据；判定失败应看 **rc 语义 + 证据**，
   二者需交叉印证，不可只看其一。
4. 此前 R-17（注册损坏）的判定**依然成立**——那次的特征是"XML 完全相同但重注册后即恢复"，
   与本次"静默即恢复"机制不同，两者不可混为一谈。
