## 二、关键风险与加固

### 风险 1：Obsidian REST（27124）依赖 Obsidian 桌面端
- **现象**：Obsidian 关闭时，obsidian_sync.py / feishu_obsidian_reconcile.py 全部失败。
- **加固**：
  - 已新增 `scripts/bridge_health_check.py` 一键自检，纳入维护链；
  - 启动维护链前先 ping 27124，不通则自动拉起 Obsidian 桌面端（待用户确认是否启用自动拉起）。

### 风险 2：feishu-mcp stdio 依赖 hermes node 环境
- **现象**：9 月 18 日曾因 hermes npm-cli.js 缺失导致安装中断；已手动补依赖修复。
- **加固**：健康自检脚本已监控 `node.exe` 与 `cli.js` 存在性；任何 MCP 工具在 AnythingLLM 里调不通时，先跑自检。

### 风险 3：飞书群轮询非事件推送
- **现象**：群指令响应延迟 = 轮询间隔；事件量大时可能漏。
- **现状**：已有 service_watchdog / heartbeat / boot_recover 三层看门狗兜底，可接受。
- **后续优化**（非必须）：飞书长连接（WebSocket 模式）可进一步降延迟，列为 V46 候选。

### 风险 4：Coze Bot 未发布（code=4015）
- **现状**：coze_gateway.py 已做"未发布时返回明确提示，不阻塞主系统"。
- **用户侧待办**：到 coze.cn 控制台把 Bot `767814502994550291` 发布到 "Agent As API" 渠道。
