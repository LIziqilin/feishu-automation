## 第一章 快速开始

### 1.1 三分钟上手（今天就能用的最小流程）

**你只需要做 3 件事：**



| 步骤 | 操作                    | 耗时        | 手机端  |
| -- | --------------------- | --------- | ---- |
| 1  | 早上 07:30 收早报，看到今日复习卡片 | 0 秒（自动推送） | ✅ 可用 |
| 2  | 在群里回复「会」「不会」「模糊」答题    | 5 秒 / 题   | ✅ 可用 |
| 3  | 收到回执，确认记录成功           | 0 秒（自动回执） | ✅ 可用 |

**就这么简单。** 系统会自动：



* 记录你的答题流水

* 计算间隔重复算法（下次复习时间）

* 更新卡片状态（NOT\_STARTED→LEARNING→REVIEWING→MASTERED）

* 每天早 / 午 / 晚推送学习内容

* 周日自动生成复盘报告

### 1.2 系统能帮你做什么（一句话说清）

**这是一个飞书群里的间隔重复学习助手。** 你在群里答题，它帮你记住、安排复习、推送提醒、生成复盘。

**核心功能：**



* 📇 每日复习卡片推送（早 / 午 / 晚，含待办合并）

* ✅ 答题记录与间隔重复算法

* 📝 随手记洞察（「洞察：xxx」）

* 📋 待办全生命周期（「待办：xxx」创建 / 「完成 xxx」销项 / 「归档 xxx」归档）

* ⏰ 到期提醒（每日03:00自动检查未来3天到期任务）

* 🔍 知识问答（「问：xxx」，三顺位降级：AnythingLLM→DeepSeek→本地检索）

* ↩️ 答题撤回（「!revoke」）

* 📊 周日复盘报告

## 第三章 日常使用场景

### 3.1 早上收早报→答题→看回执（含截图说明）

**场景：** 早上 07:30，你收到早报推送。

**步骤：**



| 步骤 | 操作                   | 你会看到                                                       | 耗时      |
| -- | -------------------- | ---------------------------------------------------------- | ------- |
| 1  | 打开飞书群，查看早报           | 📇 今日复习：3 张卡片1. 问题：什么是事件溯源？2. 问题：间隔重复的核心？3. 问题：INIT 流水的作用？ | 0 秒（自动） |
| 2  | 回忆第 1 张答案，回复「会」或「不会」 | （你输入文字）                                                    | 5 秒     |
| 3  | 收到回执                 | ✓ 已记录，下次复习：2026-09-15当前状态：LEARNING，连续正确：1                  | 0 秒（自动） |
| 4  | 继续答第 2、3 张           | 回复「不 2」「会 3」                                               | 10 秒    |
| 5  | 完成，关闭飞书              | （系统自动记录 + 更新状态）                                            | 0 秒     |

**总耗时：** 约 15-30 秒 / 3 张卡

**手机端：** ✅ 完全可用，飞书 App 直接回复文字即可

### 3.2 答错了想改 / 想撤回

**场景：** 你刚答了「会」，但突然发现记错了，想改成「不会」。

**方法 1：同日改判（推荐）**



* 直接再发一次「不会」（同一卡片同日多次答题，取最后一条）

* 系统自动标记前一条为 superseded，不参与计数

* 回执：✓ 已记录（同日改判，前一条已取代）

**方法 2：撤回**



* 发「!revoke」撤回最近一条

* 回执：↩️ 已撤销最近一条答题记录

* 然后重新答题

**方法 3：管理员修正（仅白名单）**



* 发「!admin override \<event\_id> 会 修正错误」

* 需知道 event\_id（从流水表查询）

## 第五章 常见问题 FAQ

### Q1：我发了「会」但没收到回执，怎么办？

**A：** 系统每 10 分钟轮询一次消息，请耐心等待。如超过 15 分钟仍无回执：



1. 发「?」测试系统是否正常响应

2. 如「?」也无回执，可能是轮询任务未运行，参考第六章故障自助

3. 如「?」有回执但「会」无回执，检查是否有当日复习卡片（发「?」查看）

### Q2：同日多次答同一张卡，以哪次为准？

**A：** 以最后一次为准。系统会自动将前一条标记为 superseded（已取代），不参与计数和 derive。这就是「同日改判」机制。

**注意：** 23:59 和次日 00:01 的答题，如时间差 < 6 小时，视为同一复习日（6 小时宽限期）。

### Q3：INIT 是什么？为什么有些卡片有 INIT 流水？

**A：** INIT 是卡片初始化流水。每张新卡片创建时会写入一条 INIT 类型流水，作为卡片存在的标记。INIT 流水不参与答题计数和 derive，仅用于标识卡片。

### Q4：卡片状态有哪些？怎么升级？

**A：** 卡片状态机：



```
NOT\_STARTED（未开始）→ 首次答题 → LEARNING（学习中）

→ 连续正确≥3 → REVIEWING（复习中）

→ 连续正确≥5且复习次数≥3 → MASTERED（已掌握）

→ 180天无反馈或人工归档 → ARCHIVED（已归档）
```

答错会重置连续正确计数，可能导致降级。

### Q5：归档的卡片还能答题吗？

**A：** 不能。已归档（ARCHIVED+cold\_archived=true）的卡片：



* 不会出现在每日复习队列中

* 答题会被拒绝，回执「❌ 该卡片已归档，无法答题。如需重新学习，请先取消归档。」

* 不写入流水

如需重新学习，需管理员取消归档（将 cold\_archived 设为 false，状态改为 LEARNING）。

### Q6：倦怠模式是什么？怎么恢复？

**A：** 倦怠模式是系统检测到学习疲劳时自动降速的机制：



* 触发条件：连续答错 / 学习强度过高（具体阈值由 FatigueManager 判断）

* 效果：每日复习卡片数从 3 降为 1

* 持续时间：7 天

* 自动恢复：7 天到期后自动恢复为每日 3 张

* 手动恢复：发「恢复」可提前恢复

### Q7：!admin override 怎么用？我能用吗？

**A：** !admin override 是管理员修正流水的指令，仅白名单用户可用。



* 格式：`!admin override <event_id> <new_result> [reason]`

* 示例：`!admin override om_xxx 会 修正之前错误的答题`

* 非白名单用户执行会被拒绝，并记录审计日志

* 如确需修正，请联系管理员

### Q8：知识问答的四顺位降级是什么意思？

**A：** 知识问答有四个来源，按优先级依次尝试，前一个不可用就降级到下一个：



1. **AnythingLLM 本地知识库**（第一顺位，需本地运行[http://localhost:3001](http://localhost:3001)）

2. **DeepSeek API**（第二顺位，需网络 + API 密钥）

3. **Coze**（第三顺位，❌ 当前 DEGRADED，无密钥，预留实现，不可用）

4. **飞书表格知识索引检索**（兜底，始终可用）

如前三个都不可用，会使用兜底的本地检索，结果可能不够精准。

### Q9：怎么查看我的学习进度？

**A：** 目前可通过以下方式查看：



1. 每日早 / 午 / 晚报中包含学习进度摘要

2. 周日复盘报告包含详细 ROI 数据

3. 如需实时查询，可在飞书多维表格中查看学习卡表（tblpLvxyYpDJgF92）和复习流水表（tblbznzCSpPhSz93）

### Q10：系统会泄露我的数据吗？

**A：** 数据存储在你自己的飞书多维表格中，API 密钥存储在本地 config\_local.py（不提交 Git）。系统不会向第三方发送你的学习数据。知识问答时，问题会发送到 AnythingLLM/DeepSeek/Coze 获取答案，但答题流水和洞察数据仅存储在飞书表格中。

## 第六章 故障自助

### 6.1 我发了消息没反应怎么办？

**自助排查步骤（按顺序）：**



| 步骤 | 操作            | 预期结果                                     | 如异常           |
| -- | ------------- | ---------------------------------------- | ------------- |
| 1  | 等 10 分钟（轮询周期） | 收到回执                                     | 继续步骤 2        |
| 2  | 发「?」测试        | 收到「📇 今日复习：N 张」                          | 继续步骤 3        |
| 3  | 检查飞书网络连接      | 能正常收发其他消息                                | 网络问题→检查网络     |
| 4  | 确认在正确的群       | 在 oc\_1fe154e172ab04622b7ffa810ac172bc 群 | 发错群→换到正确群     |
| 5  | 如以上都正常仍无反应    | 轮询任务可能未运行                                | 参考 6.4 手动触发轮询 |

**手动触发轮询（需电脑端）：**



```
cd "D:\AI-Tools\feishu\V13方案增强\scripts"

python run\_poll\_wrapper.py
```

### 6.2 数据好像没记录怎么办？

**自助排查：**



1. 确认收到了「✓ 已记录」回执（如未收到，参考 6.1）

2. 发「?」重新查询当日卡片，确认状态是否更新

3. 如状态未更新，可能是 derive 延迟，等 5 分钟后再查

4. 如仍未更新，可能是流水写入失败，检查是否有 DLQ 告警

5. 如持续异常，记录时间和指令内容，联系管理员排查

### 6.3 收到告警怎么办？

**告警类型与处理：**



| 告警内容            | 级别 | 处理                 |
| --------------- | -- | ------------------ |
| 权限失效 / Token 过期 | P0 | 重新认证 lark-cli（电脑端） |
| 解析失败            | P2 | 检查指令格式，参考指令速查表     |
| 写入失败 / DLQ 非空   | P1 | 系统会自动重试，如持续出现联系管理员 |
| 降级告警（LLM 降级）    | P2 | 正常现象，知识问答降级到下一层    |
| 熔断告警            | P1 | 等待自动恢复（30 秒探测周期）   |
| 凭据漂移            | P1 | 联系管理员轮换凭据          |
| 静默失败            | P0 | 联系管理员排查            |

**如告警风暴（短时间内大量告警）：** 系统会自动去重（1 小时内同类告警只发 1 条 + 1 条摘要），如仍刷屏，联系管理员检查去重逻辑。

### 6.4 什么时候需要人工介入？

**需要人工介入的场景：**



1. 发消息持续无反应（超过 30 分钟，且「?」也无回执）

2. 数据持续未记录（超过 1 小时，且有回执但状态未更新）

3. P0 告警（系统不可用 / 数据丢失 / 安全漏洞）

4. 管理员修正需求（!admin override，需白名单）

5. 卡片归档 / 取消归档（需管理员操作）

6. 备份恢复（需电脑端操作，参考《系统维保资料》第三章）

7. 系统配置变更（需电脑端修改 config\_local.py）

**人工介入方式：**



* 电脑端执行脚本（参考《系统维保资料》附录 A 命令速查）

* 联系系统管理员（白名单用户）

### 7.3 使用注意事项



1. **指令格式要准确：** 参考第二章指令速查表，格式错误会收到「❓ 没看懂」

2. **答题索引从 1 开始：** 「会 1」对应当日第 1 张卡，不是第 0 张

3. **同日改判取最后一条：** 多次答同一张卡，以最后一次为准

4. **撤回不删除流水：** 撤回是写入 REVOKE 流水，事件溯源可追溯

5. **管理员指令需白名单：** !admin override 仅白名单用户可用

6. **知识问答可能延迟：** 四顺位降级可能需要 10-30 秒

7. **归档卡无法答题：** 已归档卡片答题会被拒绝

8. **倦怠期每日 1 张卡：** 触发倦怠后每日复习降为 1 张，7 天自动恢复

9. **测试数据会被清理：** 不要使用 TEST\_前缀发送正式数据

10. **备份很重要：** 系统变更前会自动备份，如手动变更请先备份

## 第八章 Obsidian 知识库同步使用指南（V14 新增）

### 8.1 功能概述

飞书系统与 Obsidian 知识库已实现**单向同步**（飞书→Obsidian），支持：
- **待办任务同步**：飞书任务表 → Obsidian 任务笔记（按状态分类）
- **洞察笔记同步**：飞书洞察表 → Obsidian 洞察笔记（按科目分类）
- **交互式看板**：Dataview 动态查询，实时展示任务/洞察状态
- **双链关联**：洞察笔记自动生成关联学习卡片/关联任务的双向链接

**同步方式**：Obsidian 插件 JS 直连（不用 Python 桥接），自包含脚本，零外部依赖。

### 8.2 前置条件（一次性配置）

| 项 | 状态 | 说明 |
|---|---|---|
| Obsidian 版本 | ✅ 1.13.7+ | 需支持 DataviewJS |
| Dataview 插件 | ✅ 已安装 | 需启用「Enable JavaScript Queries」 |
| Local REST API 插件 | ✅ 已启用 | v5.1.0，端口 27124 |
| 飞书自建应用 | ✅ 已配置 | App ID/Secret 已写入同步脚本 |
| 飞书多维表格权限 | ✅ 已开通 | 应用已添加为协作者 |

**如果 DataviewJS 未启用**：
1. 打开 Obsidian 设置（`Ctrl+,`）
2. 左侧 → 第三方插件 → Dataview
3. 找到「Enable JavaScript Queries」→ 开启（开关变蓝色）
4. 关闭设置

### 8.3 一键同步（推荐）

**同步待办任务 + 洞察笔记（同时执行）**：

1. 在 Obsidian 左侧文件列表，打开 **「一键同步.md」**

   ```
   ✅ 一键同步全部完成（耗时 X.X 秒）
   ```

## 第十章 定时自动同步与增量同步（V14 优化新增）

### 10.1 定时自动同步（启动时自动执行）

#### 10.1.1 功能概述

支持将 Obsidian 设置为**启动时自动同步**，无需手动操作：
- 每次打开 Obsidian 时，自动执行待办+洞察+学习卡片同步
- 不新增调度任务（遵循一进一出原则）
- 不用 Python 桥接（在 Obsidian 内用 JS 执行）
- 基于增量同步优化，速度快（3-10秒）

#### 10.1.2 设置方法（一次性配置）

1. 打开 Obsidian 设置（快捷键 `Ctrl + ,`）
2. 左侧菜单 → 找到「核心插件」→ 点击「页面」
3. 找到「启动时打开特定页面」选项 → 点击开关开启（变蓝色）
4. 在下方输入框中输入或选择「一键同步」
5. 关闭设置窗口
6. 重启 Obsidian 验证：启动后应自动打开「一键同步」笔记并开始同步

#### 10.1.3 使用方法

设置完成后，**无需任何操作**：
- 每次打开 Obsidian，同步会自动执行
- 等待 3-10 秒，页面显示同步结果
- 如不需要自动同步，关闭设置中的「启动时打开特定页面」即可

#### 10.1.4 手动同步（备用）

如需要手动触发全量同步（如增量同步漏检时）：
1. 打开「一键同步.md」
2. 按 `Ctrl + E` 切换到阅读模式
3. 等待 15-30 秒，全量同步完成

### 10.2 增量同步优化

#### 10.2.1 功能概述

同步已优化为**增量同步**：
- 只同步有变化的记录，未变化的记录跳过
- 首次同步：全量写入（与原方案相同）
- 后续同步：只写入有变化的记录（通常 0-5 条）
- 同步速度：从 15-30 秒提升到 3-10 秒

#### 10.2.2 同步结果说明

同步完成后，页面显示：
```
✅ 一键同步完成（增量同步，耗时 X.X 秒）

✅ 待办任务：42 条
- 新建：0 | 更新：2 | 未变化（跳过）：40 | 失败：0

✅ 洞察笔记：19 条
- 新建：0 | 更新：0 | 未变化（跳过）：19 | 失败：0

✅ 学习卡片：19 张
- 新建：0 | 更新：1 | 未变化（跳过）：18 | 失败：0
```

- **新建**：飞书中新增的记录，Obsidian 中创建新笔记
- **更新**：飞书中有变化的记录，Obsidian 中覆盖更新笔记
- **未变化（跳过）**：飞书中无变化的记录，跳过不写入
- **目录迁移**：状态变化导致目录变化（如待办→已完成）时，自动删旧位置、写新位置，不留双份
- **删除孤儿**：飞书已删除的记录，本地同步笔记一并清理
- **失败**：同步失败的记录（通常为 0）

#### 10.2.3 状态文件

增量同步的状态保存在 vault 根目录的 `.sync_state.json` 文件中：
- 记录上次同步时间（`last_sync_time`）
- 记录每条记录的内容哈希（`hashes` 字典）
- 同步完成后自动更新
- 如文件损坏或丢失，下次同步会自动重建（执行全量同步）

**注意**：`.sync_state.json` 是系统文件，不需要手动编辑。如删除该文件，下次同步会执行全量同步。

### 10.3 常见问题

#### Q1：设置启动自动同步后，Obsidian 启动时没有自动同步？

**A**：
1. 确认「一键同步.md」文件存在于 vault 根目录
2. 确认设置中「启动时打开特定页面」已开启，且选择了「一键同步」
3. 确认 Obsidian 版本支持该功能（1.0+ 版本均支持）
4. 如仍不生效，可手动打开「一键同步.md」+ `Ctrl+E` 触发同步

#### Q2：增量同步漏检了某些变化？

**A**：
1. 增量同步基于内容哈希比较，如飞书中修改了非关键字段（如系统字段），可能不会触发同步
2. 如发现漏检，可手动执行「一键同步.md」全量同步
3. 全量同步会覆盖所有笔记，确保数据一致
4. 全量同步后，增量同步状态会自动更新

#### Q3：删除 `.sync_state.json` 会怎样？

**A**：
1. 删除后，下次同步会执行全量同步（与首次同步相同）
2. 全量同步完成后，会自动重建 `.sync_state.json`
3. 不会丢失数据，只是同步速度会变慢一次
4. 不建议手动删除，除非需要强制全量同步

#### Q4：启动自动同步会影响 Obsidian 启动速度吗？

**A**：
- 增量同步通常只需 3-10 秒，对启动速度影响很小
- 同步在后台执行，不影响 Obsidian 的正常使用
- 如同步过程中需要操作 Obsidian，可随时切换到其他笔记
- 同步完成后，结果会显示在「一键同步」笔记中

#### Q5：可以同时使用启动自动同步和手动同步吗？

**A**：可以。启动自动同步在 Obsidian 启动时执行一次，之后如需要再次同步，可手动打开「一键同步.md」+ `Ctrl+E` 执行全量同步。两种方式互不冲突。
