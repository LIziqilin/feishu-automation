## 二、优化建议清单（按价值分级）

### A 级：高价值，建议本轮落地

**A1. AnythingLLM 作为"系统知识 RAG 助手"接入**
- 现状：本系统 LLM 层（llm_config/llm_fallback/llm_guard）只做生成，无长期文档检索；AnythingLLM 有工作区 + 向量库，API 已探通（`/api/v1/workspaces` 200）。
- 优化：新建一个脚本 `anyllm_rag.py`，把本系统的最终版方案/操作手册/施工资料/用户指导手册灌入 AnythingLLM 工作区；群指令「问系统/知识：xxx」→ 走 RAG 检索回答，让"系统怎么用、某表字段、某脚本参数"可自然语言问答。
- 收益：使用便捷性大幅提升；与"越用越聪明"闭环叠加（检索结果可沉淀回洞察表）。
- 注意：AnythingLLM 当前是本地 404 部分路径——以 `/api/v1/` 前缀为准（旧脚本里 `/api/health`、`/api/auth/secure` 已失效，需按新版本 API 适配）。

**A2. Obsidian 双向同步深化（复用已连通的 Local REST API）**
- 现状：已有 feishu_obsidian_reconcile（对账）+ obsidian_reverse_archive（反向归档），Obsidian API 200 正常。
- 优化：
  1. 增加"每日笔记自动生成"：晨报/晚报推送后，把三察洞察+当日任务摘要自动写入 Obsidian 每日笔记（模板参考 workbuddy 的 obsidian-markdown.skill：frontmatter + 双向链接 + 标签）；
  2. 增加"知识卡片 ↔ Obsidian 笔记"回流：卡片表 MASTERED 卡片 → Obsidian 知识库归档（实现"学完的东西永久进知识库"）；
  3. 用 SyncTrayzor（Syncthing）对 Obsidian 库做多端同步备份。
- 收益：知识双端（飞书多维表格 + Obsidian）互为镜像，符合用户长期"Obsidian 与飞书同步"诉求；Obsidian 作为离线编辑端。

**A3. Coze 工作流接入群路由（复杂任务通道）**
- 现状：Coze token 有效、5 个工作流可用；本系统 v15_command_router 只路由到本地脚本。
- 优化：v15_command_router 增加「coze:」前缀指令 → 调 Coze API（工作流 zhishijiansuo 知识检索 / AIasistence 工作助手），把"需要多步推理/联网搜索/长文本处理"的指令转发 Coze，结果回写多维表格。
- 收益：补足本系统缺少的"复杂 agentic 任务"能力（本地只有确定性脚本+LLM 生成）。
- 注意：Coze 结果需走既有 event_log + 权限校验，防止外部内容直接入库。

### B 级：中价值，建议下一轮评估

**B1. 借鉴 Hermes Agent 的持久记忆与蓝图设计**
- 现状：Hermes 源码齐备（memory/blueprint_catalog/delivery_queue/cron），群内已有"HI，Hermes助手"。
- 优化（借鉴而非接入）：把 Hermes 的"持久记忆分层"（短期会话/长期画像/程序性记忆）思想，对照升级本系统 profile_evolve 画像表结构；把 blueprint_catalog（任务蓝图模板）思想用于本系统"任务模板库"（如 P0 特性、周复盘、月度报告等固定流程沉淀为可复用模板）。
- 收益：架构级借鉴，不引入新依赖，风险低。

**B2. 文档处理接入（MarkItDown / pdf2md）**
- 现状：本系统 todo_export_docx 只有导出；知识导入（用户发 PDF/图片笔记）无自动转换。
- 优化：群指令「导知识：附件」→ 调 MarkItDown 转 md → 写入洞察表/知识库 → 进入卡片闭环。
- 收益：打通"外部资料 → 知识库 → 复习"入口，完善知识自增长闭环。

**B3. GitHub Actions 失败告警**
- 现状：workflow 推送失败 exit 1（云端可查），但无主动通知。
- 优化：workflow 增加失败步骤（if: failure()）→ 调飞书 API 发告警到总控群（复用 api_send_message 逻辑），实现"云端挂了主动报"。

### C 级：低价值/清理项

**C1. 历史脚本与冗余目录清理（稳定性提升）**
- `D:\AI-Tools\feishu\` 根目录 50+ check_/probe_/fix_/verify_ 历史脚本 → 归档到 `_archive_历史调试`（功能已被本系统 scripts 吸收）；
- 本系统 scripts/ 内 20+ `_tmp_*`、多个 `.bak_*` 备份 → 保留最近一份 bak，其余清理；
- 目录归并：`V12方案`（旧版）、`V13鏂规澶炲己`（乱码同名）与 `V13方案增强` 并存 → 确认后归档 V12 与乱码目录，统一入口；
- 收益：降低"哪个文件在用"的认知成本，防止误改旧脚本。

**C2. 低价值客户端（元宝/千问/Qclaw）**
- 均无开放 API，本系统无法程序化调用 → 仅记录，不接入；Qclaw 安装包 555MB 未安装，可删除或留档。

**C3. tokscale / scripts（空壳）**：可删除。
