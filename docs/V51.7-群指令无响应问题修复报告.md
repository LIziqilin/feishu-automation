## 二、根因分析

### 2.1 直接根因：KeyError崩溃

**错误日志：**
```
File "task_insight_extension.py", line 852, in handle_remind
    success, result = create_task_in_table(task_data)
File "task_insight_extension.py", line 484, in create_task_in_table
    "任务名称": task_info["name"],
KeyError: 'name'
```

**原因：**
- `handle_remind`函数构造的`task_data`用的是**中文字段名**：
  ```python
  task_data = {
      "任务名称": f"⏰ 提醒：{remind_content}",
      "优先级": "中",
      "类别": "提醒",
      "截止日期": time_str,
      "备注": "..."
  }
  ```
- 但`create_task_in_table`函数期望的是**英文字段名**：
  ```python
  fields = {
      "任务名称": task_info["name"],      # ← KeyError: 'name'
      "优先级": task_info["priority"],
      "类别": task_info["category"],
  }
  ```

### 2.2 影响链：一条消息崩溃，全部消息瘫痪

```
15:43 用户发"提醒我5分钟后测试提醒功能"
  → handle_remind被触发
  → create_task_in_table(task_data) 崩溃 KeyError
  → 整个轮询脚本 exit code 1 退出
  → 后续所有消息（16:20/18:23/18:25）都不会被处理
  → 直到19:13定时任务再次运行时才读到这些消息
```

**这就是为什么15:43之后所有指令都无响应——轮询脚本在处理第一条消息时就崩溃了，后续消息全部堆积。**

## 三、修复内容

### 3.1 修复1：create_task_in_table兼容两种字段名

**文件：** `task_insight_extension.py`

```python
# 修复前：硬编码英文字段名，遇到中文字段名就崩溃
fields = {
    "任务名称": task_info["name"],      # KeyError
    "优先级": task_info["priority"],
    "类别": task_info["category"],
}

# 修复后：兼容中英文两种字段名
task_name = task_info.get("name") or task_info.get("任务名称", "未命名任务")
priority = task_info.get("priority") or task_info.get("优先级", "中")
category = task_info.get("category") or task_info.get("类别", "工作")
due_date = task_info.get("due_date") or task_info.get("截止日期")
```

### 3.2 修复2：去掉不存在的"备注"字段

**原因：** 任务表（tblz3H4lV7PCrBrX）没有"备注"字段，写入会返回not_found错误。

### 3.3 修复3：单条消息异常保护

**文件：** `learning_system.py`

在`handle_extension_command`和`handle_knowledge_command`调用处添加try-except：
```python
try:
    handled, result = handle_extension_command(text)
except Exception as _ext_e:
    print(f"[V51.7] 扩展指令处理异常: {_ext_e}")
    handled, result = False, ""
```

**效果：** 即使某条消息处理失败，轮询脚本也不会崩溃，会继续处理后续消息。

## 五、关于交互式卡片按钮"目标回调服务当前未在线"

**原因：** 交互式卡片的按钮点击需要一个Webhook回调服务端来接收POST请求。当前系统没有运行这个回调服务，所以点击按钮时飞书无法找到回调地址。

**解决方案（待办）：**
- 长期方案：运行webapi.py作为常驻服务，接收卡片按钮回调
- 短期方案：用户直接在群里发"完成：任务名"即可销项，不需要点按钮
